在 GitHub Copilot 上，通过 `skill` 工具用裸名称加载 pstack skill（`poteto-mode`、`tdd`、`architect`，而不是 `pstack:poteto-mode`）；插件的 agent 则保留前缀（`pstack:poteto-agent`、`pstack:comment-sicko`）。Copilot 的 prompt 里只会列出大型插件的部分 skill；工作流提到的每个 pstack skill 仍可按名称正常加载。`.github/copilot-instructions.md` 和 `~/.copilot/copilot-instructions.md` 算作用户指令。pstack skill 提到的每个 Claude 工具、模型、路径和内置 skill，都通过 `poteto-mode` skill 目录下的 `references/copilot-tools.md` 来解析。pstack 不附带默认的 Copilot 模型。按角色模型分派的 skill 会从用户已保存的 pstack 模型选择中取用这些模型。插件 hook 会从 Copilot 模型表 `${COPILOT_HOME:-~/.copilot}/pstack-models.md` 读取这些选择，加以校验，并把它们追加到本块的末尾。不要 `view` 这张模型表。它位于工作区之外，读取它会触发路径访问请求。在本会话中 `setup-pstack` 写入模型表之后，使用它刚写入的值。

按角色模型分派的 skill：`architect`、`arena`、`how`、`interrogate`、`poteto-mode`、`reflect`、`swarm`、`why`。
