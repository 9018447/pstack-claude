# 面向结果的执行（Outcome-Oriented Execution）

为预期的、可验证的终态优化，而不是维持平滑的中间状态。

**为什么：**让每个中间步骤都完全稳定，常常制造出变成慢性债务的临时兼容代码。应向目标架构收敛，并在明确的验证边界处证明正确性。

**核心规则：**
- 终态完整性优先于过渡期稳定
- 中间阶段的破坏只要是有计划、有范围、可逆的，就可以接受

**护栏：**
- 只用于有明确阶段边界的计划内重写和迁移
- 事先声明哪里允许临时破坏
- 迁移期间对正在触碰的区域保留高信号检查
- 计划完成时要求完整的静态与运行时验证
