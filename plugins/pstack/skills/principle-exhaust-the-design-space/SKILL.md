# 穷尽设计空间（Exhaust the Design Space）

当全新交互或架构决策没有现成先例时，先探索几个具体备选方案，再动手实现。造错东西的代价高于探索三个选项。

**规则。**当正确答案不明显时，先做 2-3 个相互竞争的原型或草图，并排比较，然后才定型。"设计两遍"说的就是这条规则。第一个形状换个口味不算数。

**适用情形：**
- 全新的 UI 交互（代码库中没有先例）
- 存在多种可行方案的架构选择
- 用户体验取决于手感而非逻辑的产品设计决策

**不适用情形：**
- 模式已确立的机械性实现
- 目标状态明确的 bug 修复或重构
- 约束决定了唯一可行方案的改动
